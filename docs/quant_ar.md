# AR 量化调研：最小的近无损精度（最终版）

日期：2026-10-07 · 机器：Xeon E5-2675 v3（16C/32T）· RTX 2070 · Vulkan 关闭 coopmat2 · torch 2.12.1+cu130

## 0. 结论（先给答案）

| 档位 | 配置 | 体积 | 分布偏移 TV(mean) | 100-token greedy | 判定 |
|---|---|---|---|---|---|
| 参考档（严格近无损） | **全 F16**，predict/emb/norm/bias/alpha 保 F32 | **158 MB**（1.96×↓） | **0.0001（CPU）/ 0.0002（Vulkan）** | 3/3 一致 | ✅ 与 f32 分布几乎不可分（≈ 后端自身噪声） |
| **全量档（推荐落地）** | **attn + ffn 用 Q8_0**，predict/emb/norm/bias 保 F32 | **89 MB**（3.5×↓） | **0.0035 / 0.0026** | 3/3 一致 | ✅ 近无损（<0.4% 概率质量偏移） |
| ✗ 不建议 | K-quant Q6_K（attn+ffn） | 70 MB | 0.0093 / 0.0080 | 1/3 ✗ | 分布偏移已近 1%，token 断续 |
| ✗ 不建议 | legacy Q5_0（attn Q8 + ffn Q5_0） | 69 MB | 0.0157 / 0.0156 | 3/3（侥幸） | 1.6% 分布偏移，无余量 |
| ✗ 崩溃 | Q4_0 / Q4_K | 50 MB | ≥0.03（token 0~2/3） | ✗ | — |

**"最小近无损" = 89 MB 的 `attn+ffn Q8_0`（TV 0.0035）；若要求分布级不可分，用 158 MB 的全 F16。**

## 1. 验收协议（三项检查，`tools/accept_quant.py` 一键跑）

```bash
python tools/accept_quant.py models/sweep/q8_attn_ffn.gguf --device cpu    # 或 --device vk
```

1. **首步 logits max|Δ|**（vs CPU-f32 golden，`GSV_AR_ACC=1`）
2. **100-token greedy 逐 token 一致**（`batch.greedy100.*`，3 条序列）
3. **分布级：教师强制(TF)探针 TV 距离** —— 关键新增。做法：用 f32 参考的 token 流固定
   上下文（逐步喂给候选模型），采样链换成**关掉 top-k 的真实分布**（top_k=0/top_p=1/temp=1/rep=1），
   转储每步概率向量（`GSV_AR_TF=1 GSV_AR_PROB_DUMP=...`），再用 `tools/compare_probs.py`
   与参考分布算全变差距离 `TV = 0.5·Σ|p−q|`。

**为什么要 TF 探针**：greedy（top_k=1）时概率向量是 one-hot，TV 非 0 即 1，指标退化；而且
greedy 门是刀刃型——单个 argmax 翻转就让后续全发散，实测出现"Δ 更大的配置反而过、Δ 更小的挂了"。
TF 探针把上下文钉死，只比较模型差异，**是唯一单调、可设阈值的指标**（阈值取 TV mean < 0.005）。

## 3. 机制结论（为什么是这个答案）

1. **输出层 `predict` 是全场最敏感的权重**。单独量化它（其余 f32，309 MB）→ TV 0.0162、greedy 2/3，
   比把 attn+ffn 全量化（89 MB）还差。→ **输出层永远保 F32**（仅 0.5 M 参数，代价可忽略）。
2. **CPU 的量化 matmul 会把激活也量化（per-32 块 / K-quant 是 per-256 块），Vulkan 不量化激活**
   （权重反量化到 f16 再乘）。因此：（a）同档位 Vulkan 比 CPU 准（q8_ffn 0.026 vs 0.059）；
   （b）**K-quant 在 CPU 上反而吃亏**（激活块更粗），在 Vulkan 上才体现"同体积更优"——
   k_q6k(70 MB) TV 0.008 优于 legacy f16_q5_0(92 MB) 0.015，但仍达不到 89 MB Q8_0 的 0.0035。
3. **Vulkan 的 coopmat2 必须关**（`GGML_VK_DISABLE_COOPMAT2=1`，进程启动前设置）：精度 6× 差异
   （logits 0.0035→0.0201）而速度几乎无差。引擎加载时会警告。
4. **embedding 必须 F32**：前端在 host 侧查表（改为图内 `get_rows` 后可放开）。
5. **量化不改善单流延迟**：Vulkan bs=1 各档位每步耗时相同（4.87 ms，launch 受限）；只有批量受益
   （bs=20：f16 1782 vs f32 1398 tok·s⁻¹，+27%）。→ 单句交互式合成用 F16 或 Q8 主要是省显存，
   批量合成才有吞吐收益。

## 4. 遗留 / 后续

- **音频级验收属于链路级**：AR 的产物是离散 semantic token，其本地判据就是"token 一致 + 分布 TV"；
  mel/音频级指标（mel-L1、说话人相似度、WER）必须在 AR→条件编码段→DiT→vocoder 全链打通后做端到端对比。
  本文件的 TV 阈值（0.005）是那一步之前的筛选门。
- K-quant 已用自研 `tools/quantize_gguf.cpp`（`ggml_quantize_chunk` + gguf 写出 API）补测完成，
  结论见上：**对本模型不划算**（同体积下 TV 略优于 legacy，但显著差于多 1.5 bit 的 Q8_0）。
- 若后续要更激进的压缩，方向不是换量化类型，而是**混合精度 + 敏感度分层**：例如只对部分层
  （浅层/tolerant 层）用 Q5_K，其余 Q8_0/F16，用 TF 探针逐层扫出可压的层集合。
